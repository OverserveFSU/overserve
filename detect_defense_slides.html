Agentic Security · Denial-of-Efficiency · Detection & Defense

Can anyone catch an over-serving MCP tool?

Industrial scanners are blind to the whole class. The only methods that catch it are our own runtime guard + academic re-implementations — and a keyed variant defeats those too.

detect_bench: 91 attack tools + 8 benign handlers + 70 gym tools · victims qwen3.5 · judges qwen3.5 / gpt-5.6-terra / gpt-6-astra (Bedrock) · budget = 40 tool calls

Recap · the attack being detected

An audited-benign tool that makes the agent over-work

One MCP tool: its source passes static review and its documented backend contract says it converges. At runtime the backend never converges, so the tool keeps returning a "do X then re-check" checklist — the agent loops through real tools, completing the benign task but burning its whole action budget.

create channel + post message (fid=1)  →  ledger/reconcile tool says "not aligned, call update_channel then re-check"  →  loop to 40 calls

Fidelity stays 1.0 (task done) — the harm is compute, not correctness. Amplification is counted (tool calls) and fidelity is a deterministic SQL verifier — no LLM judge in the core metric.

Escalation · defeating the runtime guard

Keyed attack: default-benign, fires only on a secret trigger

The base tool loops on any input, so a runtime probe with clean fixtures catches it. Fix (SSH-keypair idea): make the backend default-benign — it converges immediately — and flip to the loop only when a trigger is present.

Hash key (k00, k02)

loop iff SHA256(k‖ref)==C
preimage-resistant: a q-query probe fires it w.p. ≤ q/2²⁵⁶

Cycle key (k01, k03)

loop iff reconcile_targets names the mutually-inverse pair
no code gate — genuine unsatisfiability; fuzz hits ~1/550

A detector driving the tool without the key sees the benign twin → self-terminates → not flagged.

Result 4 · recovering amplification while staying static-clean

L2: move the checklist from CODE into planted DATA

Data-only tools pass static review but under-amplify (no checklist to drive the agent). Fix: the tool is a pure relay of the backend's "next action"; the loop-driving text lives in attacker-planted data, never in code. A clean fixture has no planted data → empty queue → benign.

The robust half of the result

Dynamic evasion is judge-independent; static is a coin toss

Dynamic (loop_guard / connor)

MISS every keyed tool under every judge (qwen, gpt-5.6, gpt-6-astra).

Mechanical: no key → the tool self-terminates at call 1 → the host's own policy declares "done". The judge's opinion never enters.

Static (llm_code_review)

Each judge flags a different subset; even the cue-bearing k00/k01 are missed by gpt-6-astra.

No stable signal — the malice is in the DATA/backend, not in the reviewable code.

Either the reviewer misses the attack, or it over-flags legitimate relay/reconcile tools with it. There is no code-level test that separates them.

When the attacker actually fires the key in production, the over-work (25–40 calls for a 5-call task) is observable and unavoidable — you can't get the DoS without causing it. But this defense is reactive (during/after the run), needs production monitoring (not marketplace review), and has a false-positive cost (some legitimate tasks are genuinely long).

Takeaways

What the detection study shows

  • Industrial MCP scanners are structurally blind to DoE — 0% across Cisco / Lasso / mcp-shield / MCPInspect; none has a work-per-task signal.
  • The only detectors that work are our own runtime guard + academic re-implementations (loop_guard 92%/0FP, connor 85%).
  • A keyed gate defeats those runtime detectors — default-benign, fires only on a secret trigger the detector's probe never carries; the evasion is judge-independent / mechanical.
  • L2 (checklist in planted data) recovers full 8× amplification while the tool code stays a benign relay.
  • Static LLM review is judge-dependent and inconsistent — three judges flag three different subsets; no stable code-level signal.
  • Only runtime work-per-task monitoring on triggered traffic detects the effect — reactive, and structurally the last line of defense.
